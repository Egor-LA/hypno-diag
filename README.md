# Опросник состояния

Система для гипнотерапевта: клиент проходит опросник в Telegram, бот присылает результаты клиенту и терапевту, напоминает о ретестах и показывает динамику.

- Бот: https://t.me/depression_test_from_egor_bot
- Опросник и карта клиента: https://egor-la.github.io/hypno-diag/
- Код: https://github.com/Egor-LA/hypno-diag

## Как это устроено

| Что | Где | Зачем |
|---|---|---|
| Опросник `web/index.html`, карта `web/report.html` | GitHub Pages | страницы для клиента и терапевта |
| Бот, приём ответов, напоминания | Supabase, функция `diag` | webhook Telegram, API, расписание |
| Данные клиентов | Supabase, база Postgres | клиенты, прохождения, расписания |
| Напоминания | Supabase, задание pg_cron раз в час | проверяет, кому пора |

Все тарифы бесплатные. Токен бота и ключи лежат только в секретах Supabase, в код на GitHub не попадают.

Изначально планировался Cloudflare, но регистрация в нём не удалась, поэтому бэкенд работает на Supabase. Тот же код запускается и на Cloudflare Workers: ядро в `worker/src`, точка входа Supabase в `supabase/entry.js`.

## Как пользоваться

1. В чате с ботом напишите `/new Имя`. Бот пришлёт ссылку вида `t.me/<бот>?start=<код>`.
2. Отправьте ссылку клиенту. Он нажимает «Старт», потом «Пройти опросник».
3. После прохождения вам приходит сводка с кнопками, клиенту приходят его результаты.
4. Чтобы включить регулярные ретесты, откройте `/clients`, выберите клиента, нажмите «Ретест» и выберите режим. По умолчанию ретесты выключены.

Если у клиента нет Telegram под рукой, дайте ему обычную ссылку https://egor-la.github.io/hypno-diag/index.html. Он введёт имя, пройдёт опросник, а в конце сможет нажать «Получать результаты и напоминания в Telegram».

### Команды бота (только из вашего чата)

| Команда | Что делает |
|---|---|
| `/new Имя` | создаёт клиента и ссылку-приглашение |
| `/clients` | список: имя, дата последнего прохождения, режим ретеста, последняя сумма; имя кнопкой открывает карточку |
| `/export Имя` | присылает .md файл со всей историей клиента (файл для ИИ) |
| `/delete Имя` | удаляет все данные клиента после подтверждения |
| `/cron` | служебная: прямо сейчас проверить напоминания |

Кнопки под сообщением и в карточке: «Открыть карту», «Файл для ИИ», «Ретест» (выбор режима, текущий отмечен ✓), «Полный ретест сейчас», «Короткий ретест сейчас». Ручной ретест расписание не сбивает.

### Режимы ретеста

| Режим | Что приходит клиенту |
|---|---|
| Полный раз в неделю | каждую неделю полный ретест |
| Полный раз в 4 недели | раз в 4 недели полный, между ними ничего |
| Короткий раз в неделю + полный раз в 4 недели | недели 1-3 короткий, неделя 4 полный |
| Выключено | ничего |

Напоминание приходит в 11:00 по местному времени клиента (часовой пояс берётся из браузера при прохождении). Нет ответа через 24 часа: одно повторное напоминание. Ещё 24 часа тишины: вам приходит «Имя не прошёл(ла) ретест», и цикл переходит на следующий срок.

Короткий ретест: 10 пунктов с самыми высокими баллами первого прохождения, оценка главного беспокойства и необязательное «Что изменилось за эту неделю».

## Как поменять вопрос или текст

- **Текст вопроса, подсказка, название сферы**: файл `web/questions.js`. Число вопросов (55) и размеры сфер проверяются при загрузке, ошибка видна сразу. Порядок менять нельзя: нумерация сквозная, пункт 39 (индекс 38) критический.
- **Формулы** (средние, выбросы, противоречия, пороги): только `web/shared.js`. Он подключается и на страницах, и в боте.
- **Тексты сообщений бота**: `worker/src/messages.js`, `worker/src/index.js`.
- **Адреса и логин терапевта для кнопки «Написать терапевту»**: `web/config.js` (страницы) и секрет `THERAPIST_TG` (бот).

После правки страниц достаточно `git push`: GitHub Pages обновится сам за 1-2 минуты. Если менялся `worker/` или `web/questions.js` / `web/shared.js` (их использует бот), нужно ещё пересобрать и выложить функцию:

```bash
npm run build
SUPABASE_ACCESS_TOKEN=<ключ> npx supabase functions deploy diag --project-ref fernvgsdytmvzrikpgqe --no-verify-jwt --use-api
```

Ключ Supabase создаётся на https://supabase.com/dashboard/account/tokens. Секреты меняются командой `npx supabase secrets set ИМЯ=значение --project-ref fernvgsdytmvzrikpgqe`. Флаг `CLIENT_SEES_RESULTS=false` отключает отправку результатов клиентам.

## Проверки

- `node test/calc.mjs`: расчёты на контрольных ответах.
- `node test/e2e.mjs`: полный цикл локально (нужны поддельный Telegram `test/mock-tg.mjs`, `wrangler dev` и статический сервер, см. начало файла).
- `node test/pg-smoke.mjs`: слой Postgres на встроенной базе.
- `node test/live.mjs`: полный цикл на живых сервисах (читает секреты из `.prod-secrets`, которого нет в репозитории). Создаёт и удаляет тестовых клиентов, поэтому вам придут тестовые сообщения.

## Если что-то сломалось

1. Бот молчит: откройте https://supabase.com/dashboard/project/fernvgsdytmvzrikpgqe/functions и посмотрите журнал функции `diag`. Проект на бесплатном тарифе «засыпает» после недели без активности; ежечасное напоминание обычно этому мешает, но если проект остановлен, нажмите там «Restore».
2. Страница не открывается: проверьте Actions в репозитории (вкладка Actions, должна быть зелёная галочка).
3. Карта пишет «Нет доступа»: ссылка устарела или неверна, откройте её заново кнопкой из чата.
4. Чат-id или токен поменялись: обновите секреты командой выше, для токена бота потом заново поставьте webhook.

## Что важно знать

- Сумма из 100 и подписи («минимальная выраженность» и т. д.) видны только терапевту. Клиенту показываются только сферы с полосками.
- Критический пункт: 1-2 жёлтая плашка, 3 и выше красная. Клиенту мягкий текст и кнопка «Написать терапевту» показываются при ответе 7 и выше.
- Это инструмент для работы терапевта, а не диагностика.
